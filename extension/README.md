# MuSync 浏览器桥（扩展）

把浏览器里正在播放的**音视频**上报给 MuSync，用于解决"系统媒体控件读不到"的情况。

---

## 1. 为什么需要它

MuSync 默认通过 Windows 的系统媒体控件（SMTC）读取浏览器播放状态。但这条链路有一个前提：

```
网页主动调用 navigator.mediaSession  →  浏览器上报给 Windows  →  系统里出现"媒体会话"
                                                                    ↓
                                       任务栏媒体浮层 / Win+A 面板 / MuSync 都从这里读
```

**必须是网页自己去发布。** 很多站点（国内小站、网盘内嵌播放器、部分直播页）根本不发布，
于是系统里连会话都没有 —— 这时**任何**按 SMTC 读取的程序都读不到（包括 Windows 自己的面板）。

这个扩展绕开这一层，直接在页面里读 `<video>` / `<audio>` 与 `navigator.mediaSession`，
把结果发到 MuSync 的本机端口。**它只上报音视频**：页面里没有媒体元素就不上报，
不会把普通网页的标题塞进你的 Steam 状态。

---

## 2. 工作原理

```
页面（content.js）
  ├─ 每秒找一次 <video>/<audio>，读 currentTime / duration / paused
  ├─ 读 navigator.mediaSession.metadata（标题/作者/专辑，B站等站点会发布）
  └─ 页面里没有媒体元素 → 什么都不做
        │  chrome.runtime.sendMessage
        ▼
扩展后台（background.js）
  └─ fetch("http://127.0.0.1:47564/media", POST, JSON)
        │
        ▼
MuSync（BrowserExtensionBridge，只监听 127.0.0.1）
  ├─ 校验并裁剪字段（标题 ≤512 字、时间 clamp 到一天）
  ├─ 有数据且 ≤5 秒新鲜 → 优先用它合成状态
  └─ 超过 5 秒没更新 → 自动回落到原来的 SMTC 路径
```

**为什么不做"读浏览器内存"**：浏览器是多进程 + V8 堆，播放状态不是一个固定偏移的字符串，
每次版本更新都会变；而且对浏览器读内存几乎是杀软眼里的标准木马行为。

## 3. 安装（Edge / Chrome，无需上架商店）

1. 打开 `edge://extensions`（Chrome 是 `chrome://extensions`）
2. 右下角打开 **「开发人员模式」**
3. 点 **「加载解压缩的扩展」**
4. 选择本目录（就是包含 `manifest.json` 的这个文件夹）
5. 装好后工具栏会出现 **MuSync Browser Bridge**（可以点图钉固定，方便看）

> 更新扩展代码后，在扩展页点一下「重新加载」；不需要重装。
> 不需要 "打包"、不需要商店账号。

---

## 4. 在 MuSync 里启用

1. MuSync → **设置 → 数据源 → 浏览器扩展增强（实验性）**
2. 勾选 **启用**
3. **监听端口**保持 `47564`（与 `background.js` 里的 `MUSYNC_PORT` 一致；要改就两边一起改）
4. 同一组里的状态行会显示：

| 状态文字 | 含义 |
|---|---|
| `未启用` | 上面没勾 |
| `等待扩展上报…` | 已开始监听，还没收到数据（去浏览器放个视频） |
| `收到：<标题>` | 正常工作中 |
| `已停止（N 秒前）` | 之前收到过，最近没更新（暂停/关闭了播放） |
| `未监听（详情见日志）` | 端口被占用等，换一个端口，或看日志 |

> 前置条件：「设置 → 同步 → **同步浏览器里正在播放的媒体（视频 / 音频）**」也要勾上，
> 扩展是这条链路的增强，不是替代开关。

---

## 5. 验证是否工作

**A. 浏览器里直接看状态**（最快）

访问 <http://127.0.0.1:47564/status>，应返回类似：

```json
{"listening":true,"port":47564,"error":"","data":{"title":"某视频","playing":true,"ageSeconds":0.4}}
```

- `data` 为 `null` → 还没收到（播放了吗？扩展装了吗？端口对吗？）
- 有数据 → MuSync 应该已经显示这个标题

**B. 看 MuSync 日志**

`%LocalAppData%\MuSync\logs\` 里最新那个文件：

```
[浏览器扩展] 已监听 http://127.0.0.1:47564/media （仅本机可访问）
[浏览器扩展] 收到：某视频（播放中）
```

## 6. 日常使用

- 装好并启用后**不需要任何额外操作**：浏览器放视频，MuSync 状态 1~2 秒内变化
- **暂停**会保持显示（状态里体现为暂停，是否隐藏取决于「音乐暂停时不在状态中显示」）
- **视频结束 / 关闭标签页**：扩展停止上报，MuSync 约 5 秒后自动清除该状态
- **切到别的站点/视频**：标题变化即更新
- 多个标签页同时播放时：**后上报的覆盖先上报的**（MuSync 只保留最近一条）
- 浏览器关闭、扩展禁用、MuSync 退出：任意一端不在，另一端会静默忽略，不影响网页

---

## 7. 支持情况

| 场景 | 说明 |
|---|---|
| B站 / YouTube / 网易云网页版 等 | 本来 SMTC 就能读到；装了扩展也没坏处（扩展数据更实时） |
| 不发布 Media Session 的站点 | **这就是它的用武之地** |
| 浏览器：Edge / Chrome / Brave / Vivaldi / Opera / Firefox | 内核支持 `chrome.runtime` 的 Chromium 系均可（Firefox 需自行调整 manifest） |
| 内置播放器的客户端（QQ音乐、酷狗等） | 不需要扩展，MuSync 直接支持 |

## 8. 排查表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `等待扩展上报…` 一直不变 | 扩展没装 / 没启用 / 端口不一致 | 检查扩展页是否启用；两边端口是否都是 47564 |
| `/status` 返回 `data: null` | 页面没有 `<video>/<audio>`，或还没开始播放 | 先点播放；直播/网盘要确认播放器真在放 |
| 状态显示的是**网页标题**而不是视频名 | 该站点没设置 `mediaSession.metadata`，扩展回退到页面标题 | 正常现象；可反馈站点，或接受标题 |
| MuSync 显示但 5 秒后消失 | 页面被挂起（后台标签休眠）或播放结束 | 关掉 Edge 的「效率模式/睡眠标签页」再试 |
| 端口占用 | 47564 被别的程序占用 | 换端口（两边一起改） |
| 装完没反应 | 扩展未获得站点权限 | 在扩展详情里确认「网站访问权限」为允许 |

---

## 9. 隐私与权限

- **只发到本机** `127.0.0.1`，扩展不联网、不上报任何数据到外部服务器
- 需要 **「读取所有网站数据」**（content script 的 `<all_urls>`）：否则无法在任意站点判断有没有音视频
- 上报内容仅：标题 / 作者 / 专辑 / 播放位置 / 总长 / 是否在播 / 站点域名
- MuSync 侧不做来源鉴权（内容只用于显示、不执行）—— 意味着**本机上任何程序都能伪造"正在播放什么"**，
  这是显示类数据的可接受取舍

---

## 10. 卸载 / 临时关闭

- 临时关闭：MuSync 里取消勾选「启用」，或在扩展页禁用扩展
- 彻底卸载：扩展页 → 移除；MuSync 里取消勾选即可（不装扩展时 MuSync 行为与以前完全一致）

---

## 11. 文件说明（想改代码的话）

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3 声明：`host_permissions: http://127.0.0.1/*`、content script 注入所有 http(s) 页面 |
| `content.js` | 页面侧：挑媒体元素、读元数据、每秒上报一次（只在有媒体时） |
| `background.js` | 后台：把消息转成 `fetch` 发到本机（service worker 有 host 权限，不受页面 CORS 限制） |

**改端口**：`background.js` 顶部的 `MUSYNC_PORT`，与 MuSync 设置里的端口保持一致。
